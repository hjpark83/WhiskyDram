위스키피디아

내 취향을 아는 위스키 사전

전문가의 언어로 쓰인 위스키를, 초보자의 언어로 다시 씁니다.

문제

정보가 없는 게 아니라,
읽어도 이해가 안 되는 것

"피티한 노즈에 셰리 캐스크의 다크 프룻, 롱 피니시"

위스키를 시작하려는 사람이 검색하면 만나는 문장이에요. 정보는 넘치는데 전부 이미 아는 사람을 위한 언어로 쓰여 있어요.

그래서 뭘 사야 할지 모르고, 아무거나 사서 실패하고, 위스키는 어렵다고 결론 내려요.

해결

아는 것만 물어보고,
마실수록 정확해져요

커피·디저트 취향 17문항→ 취향 벡터→ 입문 3병 추천→ 마시고 한 줄 후기↺

위스키 용어를 하나도 묻지 않아요. 라떼를 좋아하는지, 연기 냄새가 싫은지만 물어봐요.

후기 한 줄이 취향 벡터를 갱신하고, 다음 추천이 달라져요. 마실수록 사전이 나를 알아가요.

핵심 구조

기능이 따로 놀지 않아요

취향 프로필과 위스키 향미가 같은 7개 축을 씁니다 — 피트 · 과일 · 단맛 · 스파이스 · 꽃 · 오크 · 바디.

취향 진단

답변 → 축 점수. 질문 수가 늘면 눈금이 자동으로 조정돼요.

병 스캔

인식한 병을 같은 축으로 비교해 "내 취향 87%" 를 그 자리에서.

후기 한 줄

자유 텍스트 → 축 델타 추출 → 프로필 갱신 → 재추천.

그래서 어느 기능을 쓰든 하나의 취향이 정확해져요.

차별점 1

AI가 뭘 보고 판단했는지
보여줘요

병 스캔은 결과만 주지 않고, 라벨 사진 위에 "여기서 이걸 읽었어요" 를 그려요. 브랜드·숙성 연수·도수를 각각 어디서 봤는지 좌표로 받아 상자를 띄워요.

AI가 틀릴 수 있다는 걸 감추지 않고, 사용자가 믿을지 말지 정할 수 있게 근거를 내놓는 쪽을 골랐어요.

모델이 좌표를 뒤집어 주는 경우가 있어서 걸러내요 — 엉뚱한 자리에 상자가 뜨면 안 그리느니만 못하니까요.

차별점 2

AI를 믿지 않는 설계

사람이 확인해야 공개

AI가 웹에서 찾은 팝업 정보는 비공개 초안으로 저장되고, 관리자가 출처를 보고 확인해야 올라가요.

모르면 비워둬요

기간을 확인 못 하면 그럴듯한 날짜를 지어내지 않고 빈칸으로 둬요.

출처와 확인 날짜

공개된 화면에도 근거 링크와 "3일 전에 확인한 정보예요" 가 같이 나와요.

매일 다시 확인

정리해둔 정보는 낡아요. 매일 재확인해 바뀐 것만 제안으로 쌓고, 적용은 사람이 골라서.

차별점 3

한국에서 실제로 되는 것만

한국은 주류 통신판매가 원칙적으로 금지예요. 그래서 마트가 위스키 가격을 웹에 올리지 않아요 — 긁어올 원본 자체가 없어요.

  • 크롤링 대신 사용자 제보로 시세를 모아요. 애호가들이 원래 그렇게 해왔으니까요.
  • 용량이 다르면 비교가 안 되니 700ml 기준 환산. 평균이 아니라 중간값 — 면세점 한 건이 시세를 끌어당기면 안 되니까요.
  • 구매는 합법 경로인 스마트오더(온라인 주문 · 매장 수령)로만 이어줘요.
기술

AI가 죽어도
서비스는 살아 있어요

프로바이더 3종을 환경변수 하나로 교체해요 — Claude · ChatGPT · Gemini. 기능 코드는 손대지 않아요. 모든 AI 호출이 generateJson() · streamTurn() · researchWeb() 세 개 위에 올라가 있어요.

그리고 모든 기능에 규칙 기반 폴백이 있어요. 키가 하나도 없어도 전 화면이 돌아가요.

Next.js 16 · TypeScript · Supabase(Postgres + RLS) · Tailwind v4 · three.js · Vercel

검증

읽어서 판단하지 않고
돌려서 확인했어요

실제 Postgres

스키마 변경마다 진짜 DB를 띄워 멱등성·업그레이드·RLS를 2인 시뮬레이션으로 확인.

가짜 Gemini 서버

진짜처럼 스키마를 깐깐하게 검사해요. 키 없이도 변환 버그를 잡아냈어요 (실제로 2개).

실제 브라우저

3D 병·지구본·모바일 레이아웃은 스크린샷으로 눈으로 확인.

다음

여기서 더 갈 곳

  • 후기로 맛 데이터 보정 — 지금 향미 축은 공식 테이스팅 노트 기반 근사값이에요. 사용자 후기가 쌓이면 이 값을 실제에 맞춰 갱신할 수 있어요.
